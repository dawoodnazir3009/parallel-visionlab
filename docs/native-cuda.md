# Native CUDA build and protocol

## Build

Run install-cuda.ps1, then build-cuda.ps1, or setup.ps1 -InstallNative. The local
installer uses the official CUDA 13.5 redistributable manifest and verifies each
component SHA-256. It installs compiler/runtime support under .tools/cuda without
changing the NVIDIA driver. Build tools/CMake/Ninja come from Visual Studio.

Verified development combination: nvcc 13.5.37, MSVC 19.51.36260 (Visual Studio
2026), Windows x64, RTX 4050 Laptop GPU. CMake compiles C++17/CUDA17 with static
CUDA and MSVC runtimes and architectures 75/86/89. The native executable passed
device and output tests; dumpbin reported KERNEL32.dll as its sole static import.
The installed NVIDIA driver is still required at execution time.

Default executable: native/cuda/build/Release/visionlab_cuda.exe. Portable builds
put it beside ParallelVisionLab.exe. Override with VISIONLAB_CUDA_PATH or Java
property visionlab.cuda.path. Availability means the executable exists; a missing
or incompatible device/driver produces an explicit operation error, never a
silent CPU fallback. Use --device on the native executable to check the GPU.

## Persistent big-endian worker protocol version 2

Java starts `visionlab_cuda.exe --worker basic|tiled` once per owned backend.
The worker initializes CUDA and sends ready magic `0x50565732`. Standard input and
output carry binary frames; standard error is drained separately into a bounded
4 KiB diagnostic buffer. Windows pipes are explicitly set to binary mode.

Request: magic `0x50564c32`, width, height, operation, kernel size, reuse-input flag,
then size-squared double coefficients. ARGB words follow only when reuse-input is
zero. Requests with reuse-input one must match the cached width/height. Java only
reuses input when the exact same immutable PixelImage instance is supplied; a weak
reference avoids retaining an otherwise unloaded Java image.

Response: magic `0x50564f32`, width, height, kernel milliseconds, upload milliseconds,
download milliseconds, then width-times-height ARGB words. Java checks dimensions,
version and finite nonnegative timings before publishing output. Chunked Java I/O
and bulk native I/O avoid byte-at-a-time image transfers. No temporary image files
are created in this mode.

Device input, output, Sobel intermediate and coefficient buffers grow as required
and are reused across requests. Host staging vectors are also reused. A new input
is uploaded once; later filters on that same input reuse its device pixels. Thus
event H2D timing may contain only a coefficient upload on repeated requests.

Each request has a default 60-second deadline covering startup, request writes and
response reads. Timeout, interruption, malformed replies and process failure
invalidate and terminate the worker. A later request starts a new worker; no
failed request is automatically replayed. Owners explicitly close workers when
benchmarks finish, images are cleared/replaced, or the application exits. Worker
shutdown occurs outside measured calls and releases native host/device buffers.

Existing native executables must be rebuilt to use protocol version 2.

## Legacy file protocol version 1

The original three-argument file CLI remains available for compatibility tests
and same-session overhead comparisons; the application no longer uses it.

All integers are unsigned 32-bit words; doubles are IEEE-754 64-bit, big-endian.

Request: magic 0x50564c31, width, height, operation, kernel size, size² double
coefficients, then width×height ARGB words. Operation 0=grayscale, 1=convolution,
2=Sobel. Non-convolution requests use a 1×1 identity coefficient. The native side
validates shape (at most 64 million pixels), odd kernel size 1-31, finite bounded
coefficients, exact payload consumption and operation IDs.

Response: magic 0x50564f31, width, height, kernel milliseconds, upload milliseconds,
download milliseconds, then width×height ARGB words. Java validates total length,
dimensions, magic and finite nonnegative timings. The caller supplies input/output
file paths. This CLI exits after one image; protocol version 2 remains alive.

## Kernels

- Grayscale: one thread per pixel using the integer reference weights.
- Basic convolution: global-memory replicated-border sampling and ordered double
  accumulation. Sharpen/Gaussian use the coefficients generated by Java.
- Tiled convolution: 16×16 output block, cooperative halo loading to dynamic
  shared memory; all threads reach __syncthreads before out-of-range threads exit.
  Flattened tile indexing supports narrow/tall images without a small grid-y cap.
- Sobel: GPU grayscale followed by gradient/magnitude kernels on the same stream.

CUDA events bracket upload, kernel(s), and download separately. Initial process
startup, context creation, allocation and pipe serialization are included in Java's
first request wall time. Later calls retain pipe exchange, decoding and any needed
allocation/transfers. Benchmark warmups are excluded; a zero-warmup configuration
can include startup in measured samples. CSV distinguishes current persistent-pipe
runs from historical file-bridge records. --fmad=false reduces cross-language accumulation differences.
GPU comparison permits RGB error ≤1 and requires exact alpha. The tiled variant
optimizes memory reuse; no universal speedup is assumed.
